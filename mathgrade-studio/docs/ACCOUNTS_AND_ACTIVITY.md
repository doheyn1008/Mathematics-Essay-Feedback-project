# 계정·탐색·기여 변경

PR #1의 추가 요구사항 코멘트를 기준으로 공개 메인(`/`), 로그인(`/login`), 작업대(`/workspace`), 계정(`/account`)을 분리했습니다. 로그인 후에는 인사가 있는 메인으로 돌아오며 시작하기로 작업대를 엽니다. 로고는 세션을 유지하면서 메인으로 이동합니다. 계정·이용권·포인트는 왼쪽 아래 아바타에서 열 수 있습니다.

## 자체 계정과 OAuth

`0005_accounts_and_activity.sql`을 기존 마이그레이션 뒤에 적용해야 합니다. 자체 가입은 아이디와 scrypt 비밀번호 해시, 고정 계정 유형을 저장합니다. 7일 세션의 원문 토큰은 HttpOnly/SameSite 쿠키에만 있으며 DB에는 SHA-256 해시를 저장합니다. HTTPS에서는 Secure를 사용합니다. 로그인은 IP/아이디별 15분 제한을 적용하고 성공 시 세션을 교체합니다. 결제나 이용권은 가입으로 발급하지 않습니다.

Cloudflare는 `nodejs_compat`으로 native scrypt를 지원합니다. 운영 환경에서는 해싱 CPU 사용량에 맞는 Worker 제한을 설정해야 합니다. 비밀번호 재설정·이메일 복구·계정 탈퇴는 이번 범위에 포함되지 않았습니다. 개인정보 처리방침, 운영 지원과 공개 가입 정책을 정한 뒤 일반 회원에게 개방해야 합니다.

운영 비밀 설정은 소스가 아닌 런타임 secret으로 주입합니다.

| 공급자 | 필요한 설정 | 등록할 콜백 경로 |
| --- | --- | --- |
| Google | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `/api/product/auth/google/callback` |
| 카카오 | `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET` | `/api/product/auth/kakao/callback` |

각 콜백의 전체 HTTPS 주소를 공급자 콘솔에 등록해야 합니다. 설정이 없으면 로그인과 연동 버튼은 준비 중으로 표시됩니다. OAuth state는 브라우저 쿠키와 일회용 DB 기록에 연결되며 10분 뒤 만료합니다. Google은 PKCE와 `openid email profile`만 사용합니다. Gmail 열람 권한은 요청하지 않습니다. 같은 이메일이라는 이유로 계정을 자동 합치지 않으며, 연동은 로그인한 계정에서만 진행합니다. 공급자 access token은 사용자 정보 확인 후 보관하지 않습니다.

Sites 방문 권한과 앱의 회원 로그인은 별개입니다. 로컬의 Sites mock 사용자를 회원으로 취급하지 않습니다. 기존 ingress 계정 지원은 운영자가 `PRODUCT_HOST_LOGIN=true`로 명시적으로 활성화한 신뢰된 Sites 배포에서만 사용합니다. 기존 계정과 자체 가입 계정의 자동 병합은 하지 않습니다.

참고: [Workers crypto](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/), [Google 웹 서버 OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [카카오 REST 로그인](https://developers.kakao.com/docs/ko/kakaologin/rest-api).

## 알림 동의와 발송 경계

계정 연동은 알림 수신 동의가 아닙니다. Google 이메일/카카오 채널과 새 제출/첨삭 공개 이벤트를 각각 선택해 저장합니다. 학생 제출이 저장되면 해당 반 선생님, 공개된 첨삭 버전이 저장되면 해당 학생의 동의한 연결 채널에 outbox 기록을 만듭니다. 선생님 초안과 검토 전 비공개 AI 결과는 알리지 않습니다. 동일 이벤트·수신자·채널은 중복 생성되지 않습니다. 버전 저장과 outbox 삽입은 같은 트랜잭션입니다.

현재 발송 어댑터와 예약 발송 작업은 연결되지 않았습니다. 모든 기록은 `awaiting_provider`이며 발송 성공을 표시하지 않습니다. 이메일 제공자/발신 도메인과 카카오 비즈메시지 템플릿·발송 자격을 결정한 뒤 sender를 연결해야 합니다. 로그인용 카카오 토큰만으로 학생에게 임의 메시지를 발송한다고 가정하지 않습니다. Sender는 발송 직전 최신 동의·연결 상태와 학생 공개 권한을 다시 검사하고 안정적인 이벤트 키로 재시도를 처리해야 합니다.

## 시험 등록과 기여

일반 비공개 시험에는 출처를 요구하지 않습니다. 기존 출처는 편집 때 보존됩니다. 문항은 `1`, `1-1`, `1-2`처럼 번호를 고르는 평면 구조입니다. 기존 기록과 배정 스냅샷은 보존하며 편집 시 기존 최하위 문항 ID를 유지합니다. 제거된 집계 행에 연결되었던 기존 파일은 시험 전체 자료로 남깁니다.

시험 등록 하단의 선택 기여 항목을 펼치면 별도 기여 화면과 동일한 권리·출처·유료 제공 동의를 받습니다. 일반 시험 저장 뒤 기여를 게시하며, 두 번째 단계 실패 시 저장한 시험으로 재시도할 수 있습니다. 새 시험 생성 요청 키와 기여 고유 제약으로 응답 유실·재시도에 따른 중복 시험/적립을 막습니다. 문제지와 문항 번호·배점만 공개 스냅샷으로 투영하며 해설·기준 텍스트·학생 정보·대화는 제외합니다. 문제지 파일 안에 들어 있는 개인정보나 해설까지 자동 분리하는 기능은 없으므로 제공 전 확인이 필요합니다.

## 포인트와 유효 사용

- 최초 기여 보상은 기존 `CONTRIBUTION_POINTS` + `CONTRIBUTION_POLICY_VERSION` 설정을 사용합니다.
- 사용 보상은 `CONTRIBUTION_USE_POINTS` + `CONTRIBUTION_USE_POLICY_VERSION`이 모두 유효할 때만 적립합니다. `1P`는 확정 가격이 아니며 기본은 미설정입니다.
- 유효 사용은 개인 프리미엄 회원이 가져온 기여 문제로 **첫 AI 첨삭을 성공적으로 완료**한 경우입니다. 같은 기여·학습자에게 한 번만 적립하며 열람·가져오기·새로고침·실패·재제출은 추가 적립하지 않습니다. 철회된 기여와 본인 이용에는 지급하지 않습니다.
- 사용 보상은 AI 결과·사용량과 같은 트랜잭션에 기록합니다. 기여 적립, 사용 적립, 구매, 사용을 원장에서 구분합니다. 정책이 없던 기간의 소급 적립은 하지 않습니다.
- 포인트 별도 구매 화면은 준비 중이며 구매 API는 `PAYMENT_NOT_CONFIGURED`를 반환합니다. 상품·단가·사용처 확정과 검증된 결제 웹훅의 중복 방지 처리가 연결되기 전에는 브라우저 요청으로 잔액을 올리지 않습니다.

## 검증

권한·파일·비공개 초안·PDF·기여 관련 기존 테스트에 자체 계정/세션·추측 제한·시험 생성 재시도·기여 투영·알림 동의와 공개 시점·첫 성공 사용 보상 검사를 추가했습니다. Bash 전용 인프라 검사는 Windows에서 생략하고 Linux CI에서 유지합니다. 외부 OAuth의 실제 계정 로그인·알림 발송·결제는 운영 설정이 없어서 실연결 검증하지 않았습니다.
