# Q.E.D. 관리자

`/admin`은 Q.E.D.의 회원 목록과 상세 화면을 제공한다. 이름과 서비스 아이디로 검색하고 계정 유형으로 목록을 좁힐 수 있다. 전체 가입 인원과 학원용 선생님·학원 학생·개인 학습자·유형 미등록 인원은 현재 계정 유형을 기준으로 집계한다. 검색 결과 수는 별도로 표시한다.

사이트 소유자는 Q.E.D. 상단의 **관리자 센터** 버튼으로 이동할 수 있다. 관리자 센터 상단의 **Q.E.D.로 이동** 버튼으로 서비스 화면에 돌아온다. 관리자 센터 버튼은 서버가 관리자 권한을 확인한 뒤 표시된다.

## 회원 유형 변경

회원 관리에서 회원을 연 뒤 **서비스 계정 유형**을 선생님, 학원 학생, 개인 학습자 중 하나로 지정하고 저장한다. 저장된 유형은 Q.E.D.의 메뉴와 서버 권한 검사에 반영된다. 유형을 변경하면 이전·이후 유형, 변경한 관리자와 시각을 서버 감사 기록에 저장한다. 유형 지정과 유료 이용권 발급은 별도 기능이다.

현재 반에 소속되어 있거나 반의 이용권 부담자로 지정된 회원은 담당 관계를 먼저 정리해야 유형을 바꿀 수 있다. 변경할 유형과 맞지 않는 활성 이용권도 먼저 정리해야 한다. 안내 메시지에 해당 사유가 표시된다. 회원의 로그인 ID, 제출 기록 및 이용권 내역은 보존된다.

## Cloudflare Workers 관리자 지정

1. 먼저 실제 배포 사이트에서 자신의 Q.E.D. 계정을 가입한다. 계정 유형은 관리자 권한과 별개이므로 필요한 유형을 선택한다.
2. 운영 D1의 `product_credentials`에서 자신의 서비스 아이디에 해당하는 `user_id`를 확인한다. GitHub 아이디·이메일·표시 이름과는 다른 고유 식별자다.
3. 서버 secret `ADMIN_OWNER_USER_ID`에 그 ID를 지정한다.
4. `wrangler.json`의 `vars.ADMIN_SITE_ORIGIN`에 실제 사이트의 HTTPS 원점(예: `https://qed.it.kr`)을 지정하고 다시 배포한다. 경로와 마지막 `/`를 붙이지 않는다.
5. 같은 계정으로 로그인한 뒤 메인의 **관리자 센터** 버튼 또는 `/admin`으로 이동한다.

명령 예시와 전체 배포 순서는 [운영 가이드](../../docs/OPERATIONS.md)에 있다. `DEPLOYMENT_TARGET=cloudflare`에서만 이 방식을 사용한다. 설정한 회원 ID와 유효한 세션이 모두 일치해야 하며 로그아웃·만료·탈퇴 시 관리자 접근도 사라진다. 이메일이 같거나 선생님 유형을 선택했다는 이유로 관리자 권한을 부여하지 않는다. 설정한 HTTPS 원점에서 시작한 변경 요청만 허용한다. 소유자를 바꾸려면 새 계정의 ID로 서버 설정을 교체한다. 다른 관리자는 아래 권한 관리 화면에서 추가한다.

## 다른 계정에 관리자 권한 부여

`0011_delegated_administrators.sql`을 먼저 적용한다. 회원 목록의 계정 유형 아래에 **관리자** 또는 **소유자 · 관리자**가 표시되고 상세에서도 관리자 여부를 확인할 수 있다. 회원 상세의 **관리자 권한 관리**에서 관리자 또는 일반 회원을 선택하고 저장한다. 관리자도 다른 회원에게 권한을 부여하거나 회수할 수 있다.

권한은 계정 유형 및 유료 이용권과 별도다. 새 관리자는 회원 관리와 권한 관리를 이용하지만 소유자 전용 무상 이용권이나 이용 모드 변경 권한은 받지 않는다. 본인 및 서버에 지정된 소유자의 관리자 권한은 화면에서 변경할 수 없다. 회수된 계정은 다음 요청부터 관리자 접근이 차단된다. 변경 전후 권한, 관리자 ID와 시각을 감사 기록에 남기며 동시에 수정된 기록은 최신 정보를 불러와야 한다.

배포 전 `npm.cmd run db:migrate:remote`로 마이그레이션을 적용하고 `npm.cmd run deploy`한다. 기존 `ADMIN_OWNER_USER_ID`와 운영 DB 설정을 유지한다.

## 관리자 이용 모드

Workers 소유자는 작업공간 상단의 **관리자 이용 모드**에서 선생님·학원 학생·개인 일반·개인 프리미엄을 선택한다. `0010_owner_account_modes.sql`을 먼저 적용해야 한다. 선택은 서버에 저장되어 새로고침·재로그인 후에도 유지된다. 계정 유형은 선택한 모드에 맞춰 바뀌지만 이전 반 소속·시험·제출·첨삭 원본은 삭제하지 않는다. 다른 역할로 이미 소속된 같은 반에 다시 가입할 수는 없으며 기존 역할의 모드로 돌아가면 된다.

추가 결제 없이 유료 기능에 접근하는 소유자 권한을 서버가 제공한다. 실제 이용권·구매·결제 내역을 생성하거나 기존 이용권의 잔여 횟수를 수정하지 않는다. 학원 학생 모드에는 별도 학생 이용권이 표시되지 않는다. 관리자 기능은 어느 모드에서든 유지된다. 일반 모드를 선택해도 소유자의 운영 권한 자체가 없어지는 것은 아니며, 일반 회원과 동일한 제한을 시험하려면 별도의 일반 회원 계정을 이용한다.

소유자가 비용 담당자인 기존 반은 모드를 바꾸어도 학생 제출이 계속 가능하다. AI 연결 후 내부 완료 처리에서는 소유자 부담 사용 기록을 남기되 유료 이용권 횟수나 포인트를 차감하지 않으며 기여 이용 보상도 생성하지 않는다. AI·문자·결제 미연결 기능이 이 설정만으로 연결되지는 않는다. `ADMIN_OWNER_USER_ID`를 해제·교체하면 이전 소유자의 무상 이용 권한과 모드 변경 권한은 즉시 사라진다. 마지막 선택 계정 유형과 기존 자료는 남는다.

## 기존 ChatGPT Sites 관리자

Sites 배포에서는 `ADMIN_SITE_ORIGIN`에 Sites 주소의 원점을, `ADMIN_OWNER_EMAIL`에 확인된 Sites 소유자 이메일을 설정한다. 신뢰된 Sites ingress의 인증 헤더를 확인하며 일반 회원 세션이나 선생님 유형은 관리자 권한을 부여하지 않는다. 이 이메일 방식은 공개 Workers 배포용이 아니다.

목록에는 이름, 서비스 아이디, 유형, 가입 시각을 표시한다. 상세에서는 전화번호 인증 여부와 이용권을 함께 확인할 수 있다.
