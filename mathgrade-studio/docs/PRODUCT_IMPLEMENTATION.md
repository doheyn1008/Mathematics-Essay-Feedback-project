# PR #1 제품 요구사항 반영

기준: 저장소 작성자가 남긴 [제품 요구사항 코멘트](https://github.com/doheyn1008/Mathematics-Essay-Feedback-project/pull/1#issuecomment-6898309518). 기존 서비스의 목적은 사용자가 제공한 수학 시험과 손글씨 답안의 첨삭이다.

## 계정과 이용권

- 계정 유형은 `teacher`, `academy_student`, `personal` 중 가입 시 서버에 한 번 저장한다. 계정 생성 요청으로 이용권을 발급하지 않는다.
- 유료 권한은 별도 `product_entitlements`의 상태·요금제·만료일로 확인한다. 결제 미연결 상태에서 버튼이나 URL로 유료 권한을 얻는 경로는 없다.
- 학원 학생은 별도 결제 없이 참여 코드로 반에 가입한다. 선생님은 선생님 참여 코드로 공동 담당자가 된다. 학생 코드로 선생님 권한을 얻을 수 없다.
- 반의 이용권 담당자를 명시적으로 지정한다. 다른 선생님의 이용권으로 임의 변경할 수 없고 새 비용 부담자 본인이 수락해야 한다.
- 실제 서비스에서 역할 선택은 가입 단계에만 있다. `?demo=1`의 역할 선택과 예시 이용권은 브라우저 체험에만 적용되며 서버 권한에 영향을 주지 않는다.

## 시험과 기록

- 시험은 평면 문항 번호(1, 1-1, 1-2), 배점·선택적 기준, 순서가 있는 여러 파일을 가진다. 배정 시 스냅샷을 저장한다.
- 학생 제출은 답안 파일과 선택적인 질문을 중심으로 한다. 개인 제출은 문제와 풀이 파일 또는 혼합 파일로 시작한다. 문제 본문·풀이 전체·기준의 타이핑을 요구하지 않는다.
- 파일은 문제/답안/혼합/해설/기준으로 구분한다. 최대 12개, 파일별 15MB, 합계 60MB이며 서버에서 MIME과 매직 바이트를 검사한다. 임의의 문항·학생·반 ID를 신뢰하지 않는다.
- 대리 제출은 담당 반의 학생을 선택한다. `studentId`와 `submittedBy`를 분리하고 청구 계정을 서버에서 결정한다.
- 처리 상태, 학생 공개 상태, 선생님 검토 상태는 각각 저장한다. 문항별 피드백·총점·총평·질문 답변은 버전으로 보존한다. 초안 저장으로 직전 공개 결과를 덮어 숨기지 않는다.
- 시험 상세에 해당 학생과 담당 선생님만 접근하는 대화를 연결한다. 최초 제출 질문은 채팅과 따로 보존한다.
- PDF는 최신 허용 결과의 버전·생성 시각·검토 여부를 표시하고 문항별 평가와 총평·질문 답변을 포함한다. 원본 답안·혼합 파일을 순서대로 첨부한다. 문제 파일은 자동으로 출력하지 않는다.

## 실제 AI·결제 연결과 미정 정책

현재 실제 모델 호출과 결제는 연결되지 않았다. 화면과 API는 연결 전 상태를 반환하며, AI 요청 실패를 완료된 첨삭으로 기록하거나 사용량을 차감하지 않는다. 예시 결과는 합성 체험 자료라고 표시한다.

`prepareAnalysisInput`은 문제/답안/해설/기준, 시험·문항 식별자와 추가 질문을 같은 요청 묶음으로 구성한다. 판독 → 문항 연결 → 독립 풀이 → 답안 비교 → 기준 적용 → 질문 답변 → 불확실성 확인 순서를 정의한다. 실제 모델 어댑터는 별도 연결 작업이다. `ingestAnalysisResult`는 검증된 결과를 받아 공개 모드와 검토 이력·사용량 귀속을 처리하는 서버 내부 함수이며 외부에 결과 주입 API를 열지 않는다.

가격, 구독 주기, 제공 횟수, 추가 사용료, 기타 학습 지원은 미정이다. 이용권의 횟수 제한이 설정되지 않으면 AI 실행을 허용하지 않는다. 상품 정책 확정과 결제 연동 후 신뢰된 관리자/결제 서버에서 이용권을 발급해야 한다. 브라우저에서 설정하는 관리용 API는 제공하지 않는다.

## 기여와 프리미엄 자료

- 유효한 선생님 이용권과 자체 창작/제공 허락 확인, 개인용 **유료 프리미엄 제공에 대한 별도 동의**가 있어야 기여할 수 있다.
- 미리 본 시험 revision과 실제 게시 revision이 일치해야 한다. 동의 버전·범위·시각·권리 근거·기여자를 저장한다.
- 문제로 분류된 본인 원본만 기여한다. 학생 제출, 혼합 답안, 해설·기준 원본 및 비공개 파일명을 자동 편입하지 않는다.
- 프리미엄 목록·파일·가져오기는 서버에서 `personal_premium`의 활성 이용권을 확인한다. 선생님의 기여 내역과 프리미엄 열람은 별도 권한이다.
- 파일 내용 해시와 원본 시험의 고유 제약으로 재시도·중복 기여를 방지한다. 가져온 자료는 다시 기여 보상을 받을 수 없다. 수학의 대소문자나 호환 문자를 임의 정규화하여 합치지 않는다.
- 기본 포인트 정책은 미정으로 0을 지급하고 `policy_pending`으로 남긴다. 신뢰된 런타임 설정 `CONTRIBUTION_POINTS`와 `CONTRIBUTION_POLICY_VERSION`이 함께 유효할 때만 기여와 적립을 같은 DB 트랜잭션으로 기록한다. 기존 대기 건을 소급 적립하는 운영 절차와 포인트 사용처는 미정이다.
- 철회는 신규 목록·가져오기를 중단한다. 기존 가져오기 기록과 적립 내역은 삭제하지 않는다. 이미 가져온 자료의 사본은 보존하며 원본 재열람에는 유효한 프리미엄 권한이 필요하다. 이 초기 보존 규칙은 변경 전 상품 정책·동의 문구와 함께 검토해야 한다.

## 기존 자료 보존과 배포 경계

기존 테이블과 브라우저 저장소를 삭제하지 않는다. 이전 서버 제출은 `legacy:<id>`의 한 문항 시험으로 표시하고 기존 결과·원본·출력을 열람할 수 있다. 이전 기록은 읽기 전용이며 새 제출·수정은 새 시험 구조를 사용한다. 이전 API의 POST는 production router에서 차단한다. 이전 공유 목록은 본인 기여 영수증만 반환하며, 새 프리미엄 제공 동의로 자동 전환하지 않는다.

자체 세션 인증이 기본이며 사용자 헤더 인증은 기본 비활성화다. `PRODUCT_HOST_LOGIN=true`는 신뢰한 Sites dispatch가 인증 헤더를 보증하는 배포에서만 사용한다. 자세한 설정은 [계정·활동 문서](ACCOUNTS_AND_ACTIVITY.md)를 따른다.

현재 사이트는 기존 소유자 전용 공개 범위를 유지한다. 비로그인 랜딩 화면은 앱에 구현되어 있지만 비공개 배포의 입구에서는 플랫폼 로그인이 우선한다. 학생 실제 사용을 개방하려면 별도 사이트 방문 권한 설정이 필요하다.
