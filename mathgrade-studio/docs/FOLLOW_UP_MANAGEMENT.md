# 계정·반·시험 후속 관리

대상: [PR #1 최신 개발 범위](https://github.com/doheyn1008/Mathematics-Essay-Feedback-project/pull/1#issuecomment-6917239067), 기준 커밋 `1c39c502`.

## 계정 관리

- 로그인 화면의 **아이디 · 비밀번호 찾기**에서 기존에 인증한 전화번호로 문자를 요청한다. 자체 계정의 아이디를 확인하거나 비밀번호를 재설정한다. 소셜 전용 계정은 연결 제공자를 안내하며, 자체 비밀번호를 임의로 만들지 않는다.
- 미인증 번호, 존재하지 않는 아이디·번호 조합에는 같은 일반 응답을 반환한다. 실제 제공자 승인과 등록된 번호의 HMAC 일치가 있어야 복구한다. 번호 원문과 OTP는 DB에 보관하지 않는다.
- 복구 문자는 60초 재전송 제한, 번호·IP별 한도, 10분 인증 만료와 최대 5회 확인을 적용한다. 비밀번호 재설정 증명은 해시로 저장하고 5분 만료·원자적 일회성 소비를 검사한다. 비밀번호 변경·재설정은 기존 전체 세션, 대기 중인 OAuth와 복구 증명을 무효화한다.
- 계정 설정의 비밀번호 변경은 현재 비밀번호를 확인한다. 탈퇴도 자체 계정은 현재 비밀번호를, 소셜 전용 계정은 **이미 연결된 동일 소셜 주체**의 새 OAuth 인증을 요구한다. 소셜 재인증은 계정 연결을 교체하지 않고 5분짜리 탈퇴 증명만 발급한다.
- SMS/OAuth 자격 증명이 없으면 준비 중 오류를 반환하며 복구나 본인 확인을 성공으로 표시하지 않는다. `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE_SID`, 32자 이상의 `PHONE_IDENTITY_SECRET`, 해당 소셜 client 설정은 기존 계정 설정 문서를 따른다. 실제 외부 계정·문자 전송은 운영 연결 후 별도 검증해야 한다.

### 탈퇴와 기존 자료

- 여러 반을 모두 검사한다. 운영 중인 반의 마지막 담당자나 비용 부담 선생님은 다른 선생님이 담당·비용 부담을 직접 수락하거나 반 운영을 종료해 보관한 뒤 탈퇴할 수 있다. 마지막 담당자 이탈은 DB 조건으로도 차단한다.
- 새 비용 부담자가 수락하면 아직 성공 AI 사용 원장이 없는 제출의 부담 계정도 함께 이관한다. 이미 성공한 사용량·원장·기존 첨삭 저자는 이동하지 않는다. 보관한 반에는 새 AI 사용·제출을 허용하지 않는다.
- 탈퇴 트랜잭션에서 세션·비밀번호·소셜 연결·대기 OAuth/복구·알림 설정과 반 소속을 제거하고 이용권을 비활성화한다. 탈퇴 표식을 검사하므로 과거 세션이나 호스트 인증으로 같은 계정의 기록에 다시 접근할 수 없다.
- 사용자·프로필은 참조 보존용 표식으로 남기고 이름·이메일을 정리한다. 공유된 제출의 학생 이름, 첨삭·대화의 저자 이름은 ‘탈퇴한 회원’으로 바꾼다. 기여 문제의 신규 제공도 중단한다. 다른 학생의 시험 원본·첨삭 버전·사용 원장은 삭제하지 않는다.
- 번호 중복 지급 방지용 HMAC은 재사용 가능한 계정·번호 마스크와 분리된 표식으로 남긴다. 원본 파일·파일명·자유 서술 본문의 개인정보를 자동 탐지해 완전히 지우는 기능은 포함하지 않는다.
- 자료별 보관 근거·보관기간·삭제 요청·완전 비식별화와 기여 철회 후 기존 이용분 처리 정책은 운영 전 별도로 확정한다. 임의의 보관기간이나 법률상 보존 의무를 설정하지 않았다.

## 반과 참여 코드

- 반 이름·공개 방식·비용 부담자를 변경할 수 있다. 비용 부담은 새 부담자 본인이 수락한다. 코드 두 개는 생성 이후 수정·자동 재발급하지 않는다. 선생님 관리 화면에서 학생용·담당 교사용 코드를 각각 확인·복사한다.
- 학생의 자발적 반 탈퇴는 같은 고정 코드로 재참여할 수 있다. 선생님이 내보낸 학생은 `removed` 상태가 남아 재참여가 차단된다. 선생님이 **재참여 허용**을 누르면 같은 코드로 다시 참여한다.
- 학생은 나간 뒤에도 본인 제출·공개 결과·원본 문제·답안·과거 대화를 열람한다. 작업대 반 선택기의 **나간 반의 기록**에서 찾는다. 새 제출·자료 수정·메시지 전송에는 현재 소속을 요구한다.
- 선생님이 반에서 나가면 해당 학생의 제출·대화·답안 파일 접근 권한이 즉시 사라진다. 직접 만든 문제지의 소유권과 학생 답안 접근 권한은 구분한다.
- 반 보관은 운영 종료다. 기존 소속자의 기록 열람은 유지하며 새 참여·제출·대화·시험 배정은 중단한다. 마지막 담당자는 보관한 반에서 나갈 수 있다. 코드 자체는 그대로 남는다.

## 시험·과제와 자료 버전

- 시험 자료·문항 변경은 기존 기능의 revision 충돌 검사를 유지한다. 편집 시작 시 revision을 고정하여 다른 탭의 갱신이 작성 중인 초안의 기준을 바꾸지 않게 했다. 최신 내용을 명시적으로 다시 불러와야 기준이 바뀐다.
- 시험 **보관/보관 해제**, 미사용 시험 **삭제**를 지원한다. 삭제는 관리 목록에서 제외하는 논리 삭제이며 원본 파일·재시도 키를 보존한다. 배정·제출·기여에 사용한 시험은 삭제할 수 없고 보관한다. 과제·제출은 당시 시험 스냅샷을 계속 사용한다.
- 과제 이름·기한을 바꾸거나 배정을 취소할 수 있다. 이미 존재하는 제출·첨삭은 보존하고 취소 후 신규 제출·답안 자료 수정은 막는다.
- 시험 상세의 **제출 자료**에서 기존 답안을 유지/제외하고 사진·PDF를 교체·추가해 다시 제출한다. 질문도 같은 자료 버전에 저장한다. 등록된 문제지는 보존한다.
- 최초 수정 때 자료 v1을 보존하고 이후마다 불변 자료 버전을 만든다. 파일 저장과 revision 갱신·자료 스냅샷은 하나의 DB 트랜잭션으로 연결한다. 동시 수정의 패자는 충돌을 받고 새 파일을 정리한다. 같은 요청 ID 재시도는 같은 자료 버전을 사용한다.
- 첨삭에는 기준 `materialVersion`을 기록한다. 기존 첨삭은 v1로 해석한다. 자료를 바꿔도 이전 공개 결과·비공개 초안·교사 이력을 덮어쓰지 않는다. 새 자료와 이전 결과가 다른 경우 화면에 표시하고, 선생님의 새 검토는 새 자료 버전에 귀속한다.
- PDF는 선택된 최신 허용 결과가 실제 참고한 자료 버전의 답안·질문을 사용한다. 새 파일에 이전 점수가 붙은 PDF를 만들지 않는다.
- 수정 자료의 AI 재첨삭 시점·비용은 후속 정책이다. 현재 자료 수정은 사용량을 차감하지 않고, 수정 자료의 AI 완료 훅도 정책 준비 중으로 차단한다. 기존 최초 결과 검증·성공 시 원자적 차감·중복 차감 방지는 유지한다.

## 시험 대화 자동 갱신

- `GET /api/product/submissions/:id/messages?after=...`는 매 요청마다 해당 학생 또는 현재 담당 교사인지 확인한다. 서버에서 부여한 삽입 순번 cursor로 최대 100개씩 읽는다. 같은 시각·다른 탭의 동시 전송과 기존 날짜의 메시지도 빠지지 않는다.
- 화면을 열면 대화만 갱신한다. 정상 연결에서는 3초 간격으로 확인하고, 일시 오류에는 최대 30초까지 간격을 늘렸다가 복구한다. 탭이 숨겨지면 요청을 쉬고 다시 보이거나 온라인이 되면 확인한다.
- 메시지는 ID로 병합한다. 전송은 클라이언트 요청 ID와 DB 고유 제약으로 재시도·여러 탭의 동일 요청을 중복 저장하지 않는다. 전송 중 중복 클릭을 막고 응답이 불명확한 재시도에는 같은 요청 ID를 사용한다.
- 전체 화면·성적표·첨삭 초안을 갱신하지 않는다. 기록 화면에서 나가면 타이머·이벤트 리스너·진행 중 요청을 해제한다. 권한이 사라지면 갱신을 중단한다. 메시지 읽음·입력 중 표시는 구현 범위가 아니다.

## 이번에 활성화하지 않는 기능

- 성적 추이·취약 유형 분석·오답 정리는 개인용 프리미엄의 **개발 중** 항목이다. 실제 통계·AI 분석·가상 학생 분석 결과는 만들지 않는다. 본인 기록·성적표·교사 이력·개별 PDF는 기존 권한대로 제공한다.
- 채점기준·해설·예시답안은 작성자가 전달한 뒤 출처·버전·적용 문항과 검색 근거 추적 방식을 검토한다. RAG는 우선 제안이며 현재 자료 수집·파인튜닝·영구 학습이 완료되었다고 표시하지 않는다. 대학별 자료나 가상 기준을 추가하지 않았다.
- 첨삭은 포인트 단독 이용이 가능하고 요금제는 기본 횟수 + 소진 후 할인 포인트 사용을 제공하는 방향만 기록한다. 무료 1회·포함 횟수·포인트는 구분한다. 학원 학생은 별도 결제 없이 지정 교사의 포함 횟수·포인트에 귀속한다.
- 가격·횟수·차감량·할인·기간·갱신·해지·환불·포인트 보유/사용·기여 보상은 미정이다. 기존 개발용 첫 성공 이용 적립 조건을 최종 사업 정책으로 확정하지 않는다. 현재 활성 이용권 검사는 포인트 단독 이용의 완성된 설계가 아니다.
- 법·상품 검토 전 결제·포인트 구매/소비·구독 운영을 활성화하지 않는다. 이번 작업에서 법률 검토를 실행하지 않았다.
- 실제 AI/OCR 연결 후 응답 시간·실패·비용을 확인하여 작업 대기열·진행 갱신·자동 재시도를 별도 PR에서 설계한다. 채팅 자동 갱신과 별개이며 가짜 진행률·완료 결과를 만들지 않는다.

## 적용과 검증

`0009_account_and_record_management.sql`을 기존 마이그레이션 다음에 적용한다. 스키마와 Drizzle snapshot/journal도 함께 변경한다. GitHub PR 소스 변경이며 기존 배포를 자동 갱신하지 않는다.

회귀 검사는 계정 복구·비밀번호·소셜 재인증·탈퇴, 여러 반 인계, 고정 코드·내보내기·재참여, 보관/취소, 원본·자료/첨삭 버전 보존, 동시 수정 롤백, 메시지 cursor·권한·중복, 갱신 중단·복구·백오프를 포함한다. 실제 외부 제공자 자격 증명과 운영 데이터로 테스트하지 않는다.
