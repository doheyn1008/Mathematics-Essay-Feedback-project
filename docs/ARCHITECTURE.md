# 풀이결의 실행 구조

## 이번 변경에 포함된 것

현재 사이트는 HTML, CSS, JavaScript ES 모듈로 구성된 정적 프런트엔드입니다. 별도의 프레임워크나 외부 런타임 패키지 없이 화면과 체험 흐름을 검토할 수 있습니다. Node.js는 로컬 서버, 검사, 테스트, 빌드에만 사용합니다.

```text
브라우저
  ├─ 문제·예시 리포트 표시
  ├─ 답안 작성·파일 선택·입력 검증
  ├─ 고정된 체험 리포트 표시
  └─ localStorage에 작성 내용·체험 내역 저장
```

체험 리포트는 제출한 풀이를 분석하지 않습니다. 문항별 고정 예시를 사용하고 화면에서 예시임을 표시합니다. 실제 파일의 내용도 분석하지 않으며 원본을 저장하지 않습니다. 체험 계정과 요금제 선택은 실제 인증이나 결제 권한을 부여하지 않습니다.

## 실제 서비스로 연결할 때

UI와 체험 데이터를 유지하면서 `src/services.js`의 서비스 경계를 실제 API 호출로 바꾸는 방향을 사용합니다. 브라우저 상태는 편의 기능으로 두고, 결제 여부와 이용 가능 횟수의 최종 판단은 서버에서 처리해야 합니다.

```text
브라우저
  ├─ 관리형 인증 → 로그인 세션
  ├─ 비공개 파일 저장소 → 답안 원본
  └─ 서버리스 API
       ├─ 세션·답안 소유자·이용권 확인
       ├─ 문항 ID로 문제·채점 기준·예시 답안 조회
       ├─ AI API 요청
       └─ 첨삭 결과·처리 상태·사용량 저장

결제 서비스 → 서버리스 결제 확인 API → 이용권 기록
```

### 회원과 답안 보관

관리형 인증과 DB·파일 저장소를 연결합니다. 각 답안과 리포트에는 소유자 ID를 기록하고, API와 저장소 정책에서 해당 회원만 읽고 수정할 수 있게 합니다. 브라우저가 보낸 사용자 ID만으로 소유권을 판단하지 않습니다.

원본 파일은 비공개로 저장하고 필요한 경우 만료되는 접근 URL을 사용합니다. 보관 기간, 삭제 요청, 계정 탈퇴 시 삭제 범위를 실제 서비스 정책에 맞춰 정한 뒤 구현합니다. `localStorage`는 인증·권한 검증이나 영구 기록의 근거로 사용하지 않습니다.

### AI와 채점 자료

API 키는 서버리스 실행 환경의 비밀 설정에 보관합니다. 브라우저 번들, 공개 환경변수, Git 이력에 포함하지 않습니다.

문제·채점 기준·예시 답안은 대학·연도·문항 등의 식별자로 관리하고, 첨삭 요청의 문항과 정확히 일치하는 자료를 불러옵니다. 추가 참고 자료가 필요할 때 검색 기반 보강(RAG)을 연결할 수 있습니다. 파일 업로드나 자료 검색은 모델 자체를 재학습하는 과정과 다릅니다.

사진의 수식·손글씨 인식 내용은 사용자가 확인·수정할 수 있게 하고, 실제 첨삭 품질은 전문가가 검토한 답안으로 검증합니다. 자료를 찾지 못한 문항에 공식 기준을 사용한 것처럼 표시하지 않습니다.

### 결제와 이용 횟수

구매 요청의 금액·상품·주문 소유자를 서버에 기록하고, 결제 서비스의 승인 결과를 서버에서 확인한 뒤 이용권을 부여합니다. 브라우저의 성공 화면이나 요금제 선택값만으로 권한을 만들지 않습니다.

동일 결제 알림이나 재시도가 중복 이용권을 만들지 않도록 주문 ID와 결제 이벤트를 중복 처리하지 않게 합니다. 첨삭 요청도 고유 ID로 관리하고, 동시 요청에서 잔여 횟수가 중복 사용되지 않게 DB 트랜잭션으로 예약·확정합니다. 실패한 작업의 횟수 복원과 환불·구독 취소에 따른 권한 변경도 함께 처리합니다.

### 오래 걸리는 첨삭

서버리스 실행 시간과 AI API 한도를 확인해 요청을 설계합니다. 처리가 길어지면 작업 대기열과 `대기 → 처리 중 → 완료/실패` 상태를 저장하고, 학생이 나중에 결과를 확인할 수 있게 합니다. 재시도에서 중복 과금·중복 횟수 차감이 발생하지 않도록 같은 작업 ID를 유지합니다.

## 배포와 비밀값

이번 PR의 GitHub Actions는 구문 검사, 테스트, 정적 빌드만 수행합니다. 호스팅 계정 생성, 실제 배포, 인증·결제 계약, API 키 등록은 포함하지 않습니다.

프런트엔드는 상용 운영이 가능한 정적 호스팅 또는 서버리스 플랫폼에 배포할 수 있습니다. 서버 기능과 DB·파일 저장소는 관리형 서비스를 연결하면 됩니다. GitHub 저장소는 소스와 PR 관리에 사용합니다. 유료 SaaS 서비스 자체를 GitHub Pages에서 운영하는 구성은 사용하지 않습니다.
